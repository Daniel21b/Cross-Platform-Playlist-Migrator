Playlist Migrator

Transfer your music between platforms

What Does This Project Do?

The Cross-Platform Playlist Migrator allows users to transfer their music playlists between Spotify and YouTube Music. It:

  • ✅ Authenticates with both platforms
  • ✅ Fetches playlists and tracks
  • ✅ Matches tracks across platforms using smart algorithms
  • ✅ Creates new playlists on the destination platform
  • ✅ Shows real-time progress during migration

Key Technologies

  • Frontend: Vanilla JavaScript, HTML5, CSS3
  • Backend: Node.js + Express.js
  • Spotify Integration: Official Spotify Web API (OAuth 2.0)
  • YouTube Music Integration: ytmusicapi (Python) via child processes
  • Session Management: express-session (server-side)

Why This Architecture?

Hybrid Approach:

  • Spotify: Uses official OAuth API → Node.js handles directly
  • YouTube Music: No official API → Python ytmusicapi library (most reliable)
  • Bridge: Node.js spawns Python scripts as child processes

Benefits:

  • ✅ Best library for each platform
  • ✅ Simple integration
  • ✅ Easy to maintain
  • ✅ Good performance for this use case

Spotify Authentication (OAuth 2.0)

Step-by-Step Process:

  1. User clicks "Connect to Spotify"
  2. Frontend calls: GET /auth/spotify
  3. Backend generates random state for CSRF protection and builds OAuth URL
  4. Frontend redirects user to Spotify login page
  5. User logs into Spotify and authorizes app
  6. Spotify redirects back to: /auth/spotify/callback?code=...&state=...
  7. Backend verifies state, exchanges code for tokens, stores in session
  8. Frontend updates UI to show "Connected"

Security Features

  • ✅ State parameter prevents CSRF attacks
  • ✅ Tokens stored server-side (never exposed to client)
  • ✅ HTTP-only session cookies
  • ✅ Automatic token refresh before expiry

YouTube Music Authentication

Why Different? YouTube Music has no official API. We use ytmusicapi which reverse-engineers the YouTube Music web interface.

One-Time Setup (Terminal):

cd python-service
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python3 auth_setup.py

After setup, the authentication file is saved and no per-request authentication is needed.

Overview

The migration process converts a playlist from one platform to another by:

  1. Fetching all tracks from source playlist
  2. Searching for each track on destination platform
  3. Matching tracks using fuzzy algorithms
  4. Creating a new playlist on destination
  5. Adding all matched tracks

Detailed Steps

  1. User Initiates Migration: Selects source platform, playlist, and destination
  2. Frontend Sends Request: POST /api/migrate with migration details
  3. Backend Starts Migration: Returns migration ID immediately
  4. Migration Service Orchestrates:
    • Gets valid tokens
    • Creates service instances
    • Fetches source tracks
    • Creates destination playlist
    • Matches and collects tracks
    • Adds matched tracks to playlist
  5. Frontend Polls for Progress: Updates UI every 2 seconds with migration status

How Tracks Are Matched Across Platforms

Challenge: Different platforms have different metadata formats, song titles may have variations, and artist names may differ slightly.

Solution: Fuzzy matching with scoring system

Matching Process

Step 1: Normalize Strings

function normalize(str) {
  return str
    .toLowerCase()
    .replace(/[^\w\s]/g, '') // Remove special chars
    .replace(/\s+/g, ' ')     // Normalize whitespace
    .trim();
}

Step 2: Build Search Queries

From a source track like "Bohemian Rhapsody" by "Queen", generate:

  • "Queen - Bohemian Rhapsody" (Artist - Song)
  • "Bohemian Rhapsody Queen" (Song Artist)
  • "Bohemian Rhapsody" (Just song)

Step 3: Calculate Match Score

  • Title Match: Up to 50 points (30 for partial, +20 for exact)
  • Artist Match: Up to 20 points
  • Threshold: Score ≥ 50 is considered a match

Example:

  • "Bohemian Rhapsody" by "Queen" → 70 points ✅ MATCH!
  • "Bohemian Rhapsody (Remastered)" by "Queen" → 50 points ✅ MATCH!
  • "Radio Ga Ga" by "Queen" → 20 points ❌ NO MATCH

Complete End-to-End Flow

Scenario: User migrates "My Favorites" from Spotify → YouTube Music

  1. User Action: Clicks "Start Migration"
  2. Frontend: Sends POST request to /api/migrate
  3. Backend Controller: Receives request, calls migration service, returns migration ID
  4. Migration Service (Async Background):
    • Gets tokens (Spotify access token)
    • Creates service instances (SpotifyService, YouTubeMusicService)
    • Fetches source tracks from Spotify API
    • Creates destination playlist via Python → ytmusicapi
    • For each track: Search YouTube Music, calculate score, match
    • Add all matched tracks to playlist
    • Mark as complete
  5. Frontend Polling: Every 2 seconds, polls GET /api/migrate/status/:id and updates UI with progress

Session Management

Why Sessions?

  • Tokens stored server-side (more secure)
  • HTTP-only cookies prevent XSS attacks
  • Automatic token refresh without client interaction

Python-Node.js Bridge

Node.js spawns Python child processes to execute YouTube Music operations:

const pythonProcess = spawn('python3', [
  'ytmusic_service.py',
  command,
  ...args
]);
// Collects JSON output from Python script

Error Handling

Layered error handling across service, controller, and global middleware levels ensures robust error management.

Real-time Progress Tracking

Migration state stored in memory (Map), updated during migration, and polled by frontend every 2 seconds for real-time UI updates.
